⚙️ Cyber-Engine Data Flow

  1. Identity Scanning: When an email address is scanned, the backend queries the LeakCheck API or mock generator to identify breach matches.
  2. Local Caching: All confirmed breach items are indexed into a local, high-speed SQLite database structure to generate telemetry and allow offline operations.
  3. AI Threat Analysis: If enabled, the email and raw breach data is formatted and securely dispatched to the Gemini AI API via HTTPS endpoints. It returns a tailored threat vector description and custom prioritization steps.
  4. SMTP Dispatch: When breaches are found on a monitored address, the SMTP alert dispatcher immediately fires a priority threat brief to the target inbox.

🛡️ Cryptographic Anonymity: k-Anonymity Model

To audit passwords securely without transmitting credentials to external APIs, our application uses the k-Anonymity model:

  1. The browser calculates the SHA-1 hash of the password locally:
    password ➡️ 5BAA61E4C9B93F3F0682250B6CF8331B7EE68FD8
  2. The script extracts the first 5 characters of the hash prefix: 5BAA6.
  3. The browser requests only the matching prefix block from the HaveIBeenPwned range API:
    GET https://api.pwnedpasswords.com/range/5BAA6
  4. The API returns a list of all known breached hash suffixes matching that prefix along with their incidence counts. E.g.,
    1E4C9B3F3F0682250B6CF8331B7EE68FD8:39482
  5. The javascript audits the suffix list locally. The external database server never receives your full password hash or your plain credentials.
